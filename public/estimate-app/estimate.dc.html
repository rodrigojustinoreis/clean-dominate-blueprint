Design consistency
Component system
Fifteen components carry every screen. Each is used identically in estimate, cleaning and customer modes — the mode changes the data and the permitted detail, never the shape.
{{ c.name }}
{{ c.desc }}
Estimate mode
Rooms carry inspection data and complexity. “What needs to be cleaned?”
Cleaning mode
The same rooms carry task progress and issues. “What is being cleaned?”
Customer mode
A filtered read of the same rooms — no labor, margin or internal notes. “What has already been cleaned?”
Status vocabulary
○ Not assessed ◐ Assessed ● Cleaning ✓ Completed ▲ Issue
Glyph + word + geometry — never color alone. In 3D, completed rooms also carry a ring and issues a marker.
Information architecture
One property model, three audiences
The estimate creates the property. The job operates it. The customer reads it. Nothing is re-entered between the three.
01 · Estimator, on site
Customer → Property type → Build method → Levels → Room → Condition → Scope → Photos → Room complete → Floor complete
02 · Estimator, at the truck
Digital twin → 2D plan → Analysis → Estimate engine → Crew planning → Customer preview → Send
03 · Crew, on the job
Active job → Room workspace → Task completion → Photos → Issue → Room complete → Job report
04 · Customer, private link
Live progress → Room detail → Before/after → Timeline → Home is ready → Review · rebook
Internal navigation
Home · Estimates · Jobs · Customers · More — five tabs, present only outside a walkthrough. Inside one, the tab bar is replaced by the contextual Property → Floor → Room → Scope → Review strip and a single primary action.
One-thumb rules
Every committing action sits in the bottom 180px. No field requires typing except the address. Progressive disclosure: one decision per screen, condition before scope, scope before photos.
